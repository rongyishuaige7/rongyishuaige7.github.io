# 随章节变形的粒子场

## 目标与范围

将全页随机散尘改为随阅读位置连续变形的粒子场，保留现有文案、页面布局、真实图片、主题和 URL。参考 one-person-infrastructure 的章节形变机制，不引入入场等待、WebGL、动画库或新增用户界面。

场景：首屏三组粒子；CARRY 斜向数据流；SEE 平行观测轨道；TOUCH 点阵与折线走线；发布与构建的分层检查路径；最近更新的稀疏时间轴。结构仅为装饰，不表示真实指标或构建结果。

## 架构

- `section-state.ts` 统一识别 `main > section[id]`，使用视口 45% 处的阅读线，供导航和粒子订阅。初始深链、布局变化和浏览器返回重新校准。
- `particle-scenes.ts` 保存固定种子的粒子身份、纯几何采样与 780ms 形变。中途切换从当前已绘制位置重新出发；窗口变化保留种子，减少动态时直接显示当前场景的静态目标。
- `particle-field.ts` 管理 Canvas 2D、颜色、固定时间源、随浏览器刷新绘制、DPR 上限 1.5、鼠标轻微排斥和生命周期。单个画布以低透明度叠加，缓存正文/图片的保护区域，绘制循环不读取 DOM 布局。
- 场景几何以归一化坐标保存。预定义结构线与粒子共同淡入淡出；保留少量环境尘。手机减少粒子数量，使用适合窄屏的结构。

## 风险与约束

- 文字、真实截图和既有 PCB 动画受到保护，装饰不抢占阅读与点击。保护区域随图片加载、筛选、展开、字体和布局变化刷新。
- `proof` 独立于其 `data-lane="carry"`；粒子不通过绿色宣称构建通过。
- 后台暂停；进入 BFCache 时保留状态并暂停，恢复时重启；真正离开时释放监听器与观察器。开发热更新释放旧实例。
- 无脚本或 Canvas 不可用时内容直接可读；减少动态时没有持续动画，章节或主题改变时仅重绘静态场景。

## 验证与交付

一个完整增量交付形态模型、章节共享状态和绘制器。验证包括确定性、形态差异、快速重新定向、响应式身份连续性；浏览器验证六章正反向滚动、锚点、筛选后定位、深浅主题、1440/390/320px、DPR 2、动态减少动态、后台与 BFCache 生命周期、无 JS、文字/媒体遮罩及页面异常。运行现有测试、Astro 检查和生产构建。完成后提交推送、等待对应 Pages 工作流并检查线上场景。

## 实际验收（2026-10-22）

- 24 项 Node 测试通过，包括确定性与响应式身份、六种形态差异、过渡中快速反向、与绘制频率无关的时间源、减少动态静态采样。
- Astro 检查 25 个文件，0 错误/警告；生产构建通过。使用本次重新采集的公开数据校验 11 个仓库、22 个硬件项目与 6 条更新，验证后还原仓库原有快照，不提交无关数据刷新。
- 在生产预览上完成 1440/390px、深/浅主题、DPR 2 的 24 张章节截图；六章正反向与连续跳转、导航高亮、320px 筛选和下游章节定位、深链接通过。
- 浏览器逐像素检查视口内的标题、图片、PCB strip 和状态面板，保护区域上粒子 alpha 为 0；包含吸顶说明栏的边界情况。
- 动态切换减少动态、64/96 静态预算、156/300 动态预算、主题改变后静态重绘、静止时无持续绘制通过。无 JS 时六个章节可读、Canvas 为空、主题开关隐藏。
- 模拟 `visibilitychange` 和两次 `persisted` pagehide/pageshow，验证暂停/恢复；真实导航到 404 后返回恢复绘制；非缓存离开后监听器与绘制释放。当前 Chromium 的真实历史测试未命中 BFCache，故真实缓存恢复只验证事件契约，未声称实测命中。
- headless Chrome、DPR 2 下记录 982 次绘制，Canvas CPU 绘制耗时中位数 0.10ms、P95 0.20ms、最大 0.50ms；不包含 GPU 合成耗时。
- 初期回归发现吸顶文字遮罩需跟随 sticky 边界，已修复；锚点测试需等待原生平滑滚动结束，并用 `scrollIntoView` 避免合成线程滚动时混合读取坐标，已修正测试。

Safari、Firefox、真实 BFCache 命中、读屏软件与真机耗电未验证。浏览器回归脚本使用独立临时目录保存截图、绘制耗时和结果，可在任何现有开发/预览 URL 上重跑。

## 流畅度修复（2026-10-22）

本次只修绘制节奏和运动连续性，保留文案、布局、六种形态、粒子预算和生命周期。基线 headless Chrome 的浏览器刷新间隔约 16.7ms，但粒子只在约一半回调中绘制，间隔约 33.3ms，首屏还出现一次约 49.8ms 间隔。低 Canvas 绘制耗时无法证明显示流畅，之前的数据也不包含形态计算。

开放轨迹在循环点直接从终点跳到起点；模型边界采样在 1/60 秒内可跨越上千 CSS 像素，形变时同样存在。修复采用逐次 rAF 绘制、轨迹两端及尘的视口边缘淡入淡出。780ms 形变期间固定目标采样时间，落位后才继续沿轨道流动，避免目标在过渡中跨越循环边界。

验收增加实际刷新机会与绘制次数的比例、完整绘制回调 CPU 耗时（包含模型，不含 GPU 合成），以及循环边界和形变期间的连续性测试；保留减少动态无持续绘制的断言。更高刷新率会增加绘制次数，仍以 DPR 和粒子数量限制单帧预算，后台继续暂停；真机高刷和耗电需另行实测。

追加验收：

- 26 项 Node 测试通过；时间模型在 30/60/120/144 次调用频率下得到相同结果，循环边界已不可见，原先会跨越循环点的形变连续通过。Astro 检查无错误/警告，公开数据校验及生产构建通过。
- 生产预览在桌面首屏、CARRY 和手机 TOUCH 的三个独立窗口中均为 88 次刷新、88 次绘制，间隔中位数约 16.7ms。另用受控 rAF 分别验证 60/120/144Hz 每次回调均绘制；后者验证调度契约，不代表真机高刷或 GPU 性能。
- 单独连续平滑滚动经过首屏、CARRY、SEE、TOUCH：1440/390px、DPR 2 均为 178 次刷新、178 次绘制，间隔 P95 约 16.8ms。完整回调 CPU 耗时 P95 分别为 0.8/0.9ms，最大 3.7/2.0ms，无页面异常。
- 完整浏览器回归通过 24 张章节截图、正反向与连续重定向、深浅主题、导航、筛选、深链接、保护区域、减少动态、暂停/恢复/释放和无脚本降级。其 4208 次绘制的完整回调 CPU 中位数 0.3ms、P95 0.8ms、最大 23.9ms；该回归同时进行截图与像素读回，不能据此声称所有帧始终达到 60fps。
- 真实历史返回恢复绘制，仍未命中真实 BFCache；事件契约验证保留。Safari、Firefox、真机高刷与耗电未验证。
